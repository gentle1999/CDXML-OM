# ADR 0002：语义化静态元数据组织

[English](../../adr/0002-semantic-static-metadata.md) | 简体中文

状态：已接受

## 背景

完整、基于来源的 schema 会生成数百项属性元数据、53 个元素模型、枚举、codec、子元素
路径和来源引用。将其全部放入单一模块难以维护，但按数字和文件大小切片又会使组织方式
任意。安装包的运行时还必须独立于构建期 YAML、DTD、SDK 目录和编译器。

## 决策

编译器在 `cdxml_om._generated._metadata/` 下生成并保存普通 Python 模块，按 schema 语义组织：

- 冻结的元数据类型及共享来源/数据类型常量放在专用模块；
- 每个对象和枚举各有按规范 schema ID 命名的模块；
- 属性按逻辑所属方分组，公共属性只生成一次并由相关对象导入；
- 来源常量按来源 ID 分组，符号名由来源 URI 与 locator 的稳定内容哈希派生。

`schema_metadata.py` 是保持向后兼容的轻量导出 facade。生成 wrapper、注册表、枚举和元数据
通过静态 Python import 使用；运行时不解析 JSON/YAML schema 文件，不动态解释 schema，也
不通过 `exec`/`eval`/JIT 构造模型。Python 会正常导入已保存的静态模块。编译器确定性地
排序 import 并格式化输出。它递归检查生成目录，发现意外文件会报错；只会清理带有生成文件
声明的过期 Python 文件。

## 结果

审查者可按对象、枚举、属性所属方/共享组或来源定位元数据，而不是在编号切片中查找。共享
属性元数据保持单一对象身份；增加无关来源引用不会导致既有来源符号重新编号。模块更多，
但组织方式符合规范 schema，安装后的运行时仍只导入 Python 模块。

此布局是实现组织方式，不代表完整 DTD 文法或 ChemDraw 行为。覆盖率由独立的、绑定来源的
特性证据系统报告。
